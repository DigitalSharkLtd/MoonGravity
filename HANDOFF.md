# MOON GRAVITY — handoff для новой сессии

Состояние на коммит `4b4c004`, ветка **`claude/kind-meitner-dsx4s1`** (PR не создавался). Всё
запушено. Архив для Netlify Drop: `npm run dist` → `release/moon-gravity-netlify-drop.zip`.

## 1. Что это за проект

Стилизованный (Overwatch + броня Halo/Mass Effect) sci-fi hero-шутер на Луне в браузере.
- **Стек:** three.js r186 (WebGL2), TypeScript strict, Vite 7, без внешних ассетов, кроме 55 CC0 звуков в `public/audio`.
- **Содержание:** 3 режима и 3 карты (Дуэль 2×2, FFA на Карьере, Война 4×4 на Фронте Тихо), 9 героев × 3 билда, боты 4 уровней.
- **Мультиплеер:** listen-server на WebRTC (P2P). Лобби и сигналинг — Netlify Functions v2 + Blobs.
- **Упаковка:** PWA (офлайн с ботами) и шаблон Android TWA (`twa/`).

Полное описание игры, героев, управления и деплоя — в `README.md` (актуален).

## 2. Команды

```sh
npm install
npm run dev              # :5173, лобби работает прямо в dev-сервере
npm run build            # typecheck + сборка в dist/
npm run preview          # dist/ + локальное лобби (порт по умолчанию 4173; в тестах использовался 5192)
npm run dist             # сборка + release/moon-gravity-netlify-drop.zip
npm run typecheck:server # проверка netlify/functions + shared/
npx tsc --noEmit -p .    # быстрый typecheck клиента
```

**Деплой.** С мультиплеером — подключить репозиторий в Netlify: `netlify.toml` уже настроен, функция
`netlify/functions/lobby.mts` отвечает на `/api/lobby/*`. Netlify Drop функции не запускает: там
будет только игра с ботами. Живой Netlify ни разу не проверялся.

## 4. Что сделано в этой сессии (хронологически, кратко)

1. **Модели и графика.** Броня/шлемы в стиле Halo/ME, переписаны модели оружия и техники, 55 звуков. Затем проходы по анимации (бег, приземления, дыхание), материалам, рельефу (скальные склоны, свежие выбросы). Здания стоят ровно: `Foundations.ts` выравнивает грунт под фундаментами и не трогает подножия лестниц.
2. **Сервер.** При открытии сайта игрок автоматически попадает в незаполненную комнату любого режима, а если комнат нет — сам становится хостом «Войны 4×4». `?menu` в URL отключает это. Без TURN, по решению заказчика. Повторы поиска комнаты, ожидание хоста 25 с, таймаут тишины канала 20 с.
3. **Прицел (ПКМ).** Камера на линии прицела, голографическая марка в окне коллиматора, перекрестие HUD скрыто. Оружие с ADS без прицела получает коллиматор автоматически (`mountHolo`).
4. **Движение.**
   - Бег на **Shift**. Раскладка: способности **Q/E**, ульта **X**, взаимодействие **Y**; старые настройки мигрируют.
   - Гравитация героев 5,5 м/с², прыжок ≈ 2,07 м и 1,8 с в воздухе. Тап Space — прыжок, удержание > 0,5 с — ранец (тяга 12,5; стоя на земле ранец взлетает сам).
   - Маг-ботинки при появлении **выключены** (F).
5. **Боты.** Разброс прицела растёт с дистанцией. Тонированное стекло теперь блокирует пули и обзор. Взрыв за полным укрытием не наносит урона.
6. **Производительность.**
   - Прогрев всех шейдеров под экраном загрузки (`Warmup.ts`).
   - Постоянный пул вспышек: раньше смена числа ламп перекомпилировала все шейдеры посреди боя — главная причина фризов.
   - Асинхронная компиляция мира, кэш миникарты.
7. **Мелкие фиксы.**
   - Мерцание совпадающих полов: плоские плиты визуально приподняты на 1–8 мм.
   - Трос крюка больше не остаётся висеть после возрождения.
   - Нет экрана смерти до первого появления.
   - Смена героя после смерти на Y или Enter.
   - Герой в меню стоит на кольце, левее имени, голова не упирается в верх.
   - Пункт «Полный экран» в главном меню.
   - Антенна винтовки Улья перенесена на приклад.

## 5. Проблемные места и риски (читать обязательно)

**Сеть**
- Живой Netlify не проверялся (лобби тестировалось только локально: vite middleware + 2 браузера).
- Нет TURN: игроки за симметричным NAT / строгим корпоративным файрволом не соединятся. Решение заказчика; если будут жалобы, это первое, что проверять.
- Нет миграции хоста: хост вышел — матч у клиентов закончился. Вкладка хоста в фоне: `requestAnimationFrame` останавливается, симуляция хоста встаёт.

**Производительность**
- Сборка мира ≈ 4–5 с CPU на главном потоке (из них ~2,2 с — процедурные текстуры `materials`). Кандидат на Web Worker или кэш в IndexedDB.
- Прогрев строит 9 моделей героев, всё оружие и технику на каждом старте матча (CPU). На слабых GPU прогрев = несколько секунд под экраном загрузки. В бою после прогрева компилировалось ~7 программ, после последнего фикса должно быть ~0 — **не перемерено**.
- Правило: **не включать/выключать источники света в бою** (`visible`/добавление в сцену). Число ламп зашито в шейдеры — любая смена = перекомпиляция всего.
- JS-бандл один чанк ≈ 1,75 МБ (585 КБ gzip).

**Геймплей и визуал: не проверено или проверено частично**
- Прицел после переноса антенны Улья визуально не проверен (сборка есть). ADS у Фантома (twinarc, двойное оружие) и у сингулярности не смотрел.
- Снаряды летят по лунной гравитации 1,62, а герои падают с 5,5 — осознанное решение, но баланс гранат и ракетных прыжков после смены гравитации не тюнился. Навсетка ботов считает прыжок вверх ≤ 2,0 м.
- Бронестекло поменяло линии обзора на картах — проверить, нет ли теперь «слепых» позиций.
- Внутри купола (`Complexes.ts` ~1242/1257) деревянный настил геометрически входит в стену. Мерцание убрано, а само пересечение осталось.
- Поза героя на фоне меню: руки разведены, нет нормальной idle-позы с оружием.
- `Physics.rayCollider`: луч, стартующий внутри бокса, этот бокс не видит. Если голова или глаз окажется внутри стены, выстрел пройдёт сквозь неё.
- Мерцание вдали: камера near=0.1, far=6000. Возможен reversed depth, но N8AO и постобработку надо проверять.

**Процесс**
- Тестовые Playwright-скрипты лежали в scratchpad прошлой сессии и **не в репозитории** (см. §6, как воссоздать).

## 6. Как тестировать (воссоздать быстро)

Headless Chromium + SwiftShader (в облачной среде: `executablePath: '/opt/pw-browsers/chromium-1194/chrome-linux/chrome'`,
args `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader`, для WebRTC ещё
`--disable-features=WebRtcHideLocalIpsWithMdns`). Сценарий:
1. `npm run build && npx vite preview --port 5192`.
2. Открыть `/index.html?menu` (без автоподключения) и дождаться `window.__mg.world`.
3. Вызвать `__mg.start('war4v4'|'ffa'|'duel2v2', heroId)` или `__mg.online(mode, hero, join?)`.
4. **Smoke:** сделать локального игрока ботом (`g.local.control='bot'; g.local.isBot=true`) и прогнать `g.fixedStep(1/60, i%2===0)` ~2700 раз. Ожидать 0 ошибок, kills > 0, maxY < ~10.
5. **Ввод:** выставить `__mg.input.locked = true`, затем `__mg.input.simulate('Space', true/false)`, `__mg.input.mouse[2]=true` (ПКМ).
6. **Мультиплеер:** 2 контекста браузера. Хост `__mg.online(m,h,'create')`, клиент — по коду из `__mg.net.joinLink`. Автоподключение проверяется просто открытием `/index.html` в двух контекстах.
7. **Шейдеры:** `pipe.renderer.info.programs.length` до/после старта; новые программы в бою = будущие фризы.

## 7. Общее направление (рекомендуемые следующие шаги)

1. **Выкатить на Netlify с функциями** и проверить автоподключение живьём с 2–3 устройств в разных сетях. Главный риск проекта.
2. **Плейтест-тюнинг** новой физики: высота/дальность прыжка, ранец, спринт (8+ м/с у быстрых героев), баланс взрывов и ракетного прыжка, точность ботов.
3. **Загрузка:** вынести процедурные текстуры и сборку мира в Worker или кэш; показывать прогресс прогрева.
4. **Устойчивость сети:** миграция хоста или хотя бы переподключение; обработка фоновой вкладки хоста (ограничение fps вместо остановки).
5. **Полировка визуала:** idle-поза героя в меню, пересечения геометрии в куполе, проверить ADS у всех видов оружия.
6. Разбить бандл (динамический импорт карт и редких систем) для мобильных и TWA.

Контекст по стилю работы с заказчиком: общение на русском; ценит готовые сборки (drop zip) после
каждого круга правок; бюджетно-ограничен — делать точечно, проверять автотестами, коммитить и пушить.
